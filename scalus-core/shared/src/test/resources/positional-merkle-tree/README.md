# SSZ reference vectors

`ssz-v1.5.0.json` contains 42 vectors generated by executing Ethereum's consensus-specs **v1.5.0** reference Python code with `uv run`.

Sources:

- [`ssz/simple-serialize.md`](https://github.com/ethereum/consensus-specs/blob/v1.5.0/ssz/simple-serialize.md), the `merkleize(chunks, limit)` specification. This Markdown file describes merkleization in prose; its executable implementation is [`tests/core/pyspec/eth2spec/utils/merkle_minimal.py`](https://github.com/ethereum/consensus-specs/blob/v1.5.0/tests/core/pyspec/eth2spec/utils/merkle_minimal.py): `merkleize_chunks` and `zerohashes`.
- [`ssz/merkle-proofs.md`](https://github.com/ethereum/consensus-specs/blob/v1.5.0/ssz/merkle-proofs.md): executable fenced Python definitions of `get_helper_indices`, `calculate_merkle_root`, `calculate_multi_merkle_root`, `verify_merkle_proof`, `verify_merkle_multiproof`, their generalized-index and branch/path helpers, and `merkle_tree`.

The harness executes those function bodies unchanged. It supplies their type names and the imported `hash` function. It runs twice: with `hashlib.sha256(x).digest()` (the unmodified Ethereum algorithm), then with only that hash binding replaced by `hashlib.blake2b(x, digest_size=32).digest()`. Zero hashes are initialized afresh for each run. The Scala off-chain API's custom node hash reproduces the SHA-256 cases; the default builder and on-chain code reproduce the BLAKE2b cases.

Inputs are reproducible without a random seed: element `i` is ASCII `element-{i % 7}`. Each input chunk is BLAKE2b-256 of that element in **both** runs; changing the node hash does not change the input chunks. Depths are 1, 2, 3, 4, 5, 6 and 15. For capacity `2^depth`, counts are 0, `max(1, capacity * 3 // 5)` and capacity. This covers empty, partial and full trees, including duplicate chunks. There is no length mixing.

Single positions are the sorted distinct set `{0, capacity - 1, count // 2, max(0, count - 1)}`. `occupied` distinguishes a leaf from a padded zero chunk. Multiproof queries are the first `min(4, count)` positions and the sorted distinct set `{0, count // 2, count - 1}` for nonempty inputs, plus `{0, 1, 6}` for the full depth-three case. `helperIndices` is the reference `get_helper_indices` output. Proofs concatenate the reference hashes without framing. For every single and multi query, `emptiedRoot` is obtained by zeroing those chunks and calling `merkleize_chunks` again.

The generation run checked 118 single proofs, 58 multiproofs, and 176 replacement roots with the reference verification/calculation functions, independently of Scala. The JSON is 116085 bytes including whitespace. The harness is kept outside the repository; its invocation is `uv run generate_vectors.py <output-json>`.
